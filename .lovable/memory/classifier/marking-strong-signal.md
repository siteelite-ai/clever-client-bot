Wave B (2026-06-15) — classifier-prompt.ts §"СИЛЬНЫЙ ПРИЗНАК МАРКИРОВКИ".

**Правило**: если в товарной части запроса присутствует токен-маркировка (алфавитно-цифровой код вида БУКВЫ+ЦИФРЫ, БУКВЫ-ЦИФРЫ, ЦИФРАхЦИФРА.ЦИФРА, ЦИФРА*ЦИФРА — без пробела внутри) И рядом стоит ИМЯ-БРЕНД ИЛИ числовой техпараметр с единицей (А/Вт/кВт/В/IPxx) → `has_product_name=TRUE`. Разговорная обёртка («предложи замену», «не дороже X», «есть ли») срезается на Шаге A — ядро запроса = маркировка+бренд → `product_name`.

**Краевые случаи**:
- Короткий буквенный код-маркировка (2-4 заглавные кириллические буквы, иногда с суффиксом «нг»/«нгд») — это НЕ бренд, в brand-фильтр НЕ попадает. При has_product_name=TRUE весь заголовок (включая маркировку) идёт в product_name. При FALSE — маркировка одним токеном в search_modifiers.

**Connected critical_modifiers rule** (то же место в prompt): числовые техпараметры с единицей, форм-факторы (накладной/встраиваемый/число полюсов/жил), и маркировки-коды — критичные по умолчанию (если нет смягчающих слов).

**Data-agnostic**: правила сформулированы шаблонами, БЕЗ реальных брендов/маркировок 220volt в spec. Тест `classifier-prompt_test.ts` проверяет это.

**Решает кейсы**:
- «Автомат 1Р ВА 47-29 16 А 4,5кА характеристика С GENERICA ИЭК предложи равноценную замену…» → теперь has_product_name=TRUE, product_name точечный.
- «ВВГ 3*1,5» → has_product_name=TRUE.
- В режиме FALSE: числовые токены (16А, 4.5кА) автоматически становятся critical_modifiers.
