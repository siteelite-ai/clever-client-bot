# Единица измерения в остатках товара

## Подтверждённая причина

У каждого найденного товара единица уже извлекается из API каталога и сохраняется в `ProductRef.unit`. Поэтому цена кабеля корректно рендерится как `283 ₸/м`.

Но строка наличия формируется отдельно и сейчас всегда жёстко добавляет `шт`: `${город} (${остаток} шт)`. Из-за этого карточка кабеля противоречива: цена указана за метр, а складской остаток — в штуках.

## Что изменить

1. Передавать единицу конкретного товара в форматирование складских остатков.
2. Выводить одно и то же значение API согласованно во всей карточке:
   - единица `м` → `Цена: 283 ₸/м`, `Караганда (4648 м)`;
   - единица `шт` → цена без шумового суффикса, `Караганда (12 шт)`;
   - другая единица → использовать её буквально и в цене, и в остатках;
   - единица отсутствует → не придумывать `шт`, показывать только количество.
3. Не менять поиск, сортировку, критерии или данные API.
4. Добавить тесты на остатки в метрах, штуках, другой единице и без единицы; прогнать общий набор V3-тестов и затем живой кейс с кабелем.

## Техническая часть

- Изменение локализовать в `render.ts`: `formatStockLine` получает `p.unit` и использует безопасно очищенное значение.
- Расширить `price-unit_test.ts`, проверив целую карточку, а не только строку цены.
- В живом прогоне сверить `chat_request_logs`: у карточек кабеля одновременно должны быть `₸/м` и остатки в `м`.
