# Базовая матрица клиентских регрессий AI-консультанта

Дата: 19 августа 2026 года

Production-эндпоинт: `https://yngoixmvmxdfxokuafjp.supabase.co/functions/v1/chat-consultant-v3`

База ветки: `origin/main` на `cef951b2`

## Зачем зафиксирована эта матрица

Матрица объединяет прежние сценарии заказчика и пять новых сценариев из документа от 19 августа. Она является блокирующим release gate: исправление нельзя считать готовым, если новый сценарий проходит ценой регрессии прежнего.

Проверка не использует словарь названий товаров или жаргонизмов. Она проверяет наблюдаемый контракт ответа: сохранение требований пользователя, доказательное совпадение карточек, цену, наличие объяснения, продолжение диалога, отсутствие служебных сведений и завершение SSE.

## Базовый результат до исправлений

| Группа | Результат | Реальная проблема |
| --- | --- | --- |
| Прежние клиентские сценарии | 6/7 PASS | Аналоги DN027B вернули честный пустой результат вместо товаров |
| Новые клиентские сценарии | 0/5 PASS | Поиск кабеля не дошёл до карточек; объяснение Gallant потерялось; замена автомата нарушила ограничения; простой фильтр отдал товары текстом без карточек; второй кабельный запрос остался пустым |

Три прежних многоходовых сценария сначала были помечены ошибочно. Причина находилась в QA-раннере: ответы на уточнения о ранее показанных товарах содержат цену и артикул, но закономерно не создают новые карточки. Запрет «каталожные факты без карточек» теперь включается только для ходов подбора. После коррекции люстра, бытовой светильник и наружный PoE повторно прошли.

## Условия завершения

1. Все 12 сценариев проходят локальные и API-проверки без ослабления прежних ожиданий.
2. Поиск использует структурированные ограничения, извлечённые из рассуждения, и не подменяется словарями конкретных товаров.
3. Товары поступают только через серверные карточки; ответ не перечисляет неподтверждённые каталожные факты свободным текстом.
4. Ссылки ведут на конкретные разрешённые карточки товара.
5. Продолжение диалога сохраняет исходные жёсткие ограничения.
6. После preview выполняются три независимых полных прогона, затем тот же gate повторяется на production.
7. Для каждого релиза зафиксированы commit, логи и проверяемый путь отката.
