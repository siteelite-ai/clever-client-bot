## 2. Что осталось как системный контракт (НЕ «мышление»)

- **`price > 0`** в `search-catalog.ts` — Q2 пользователя.
- **`v3_guard_text_facts_leak`** — антигаллюцинация финального текста (нельзя выключать).
- **`v3_guard_anchor_excluded`** — только исключение самого якорного SKU в режиме «аналог» — Q3.
- **`v3_guard_budget_cap`** — хард-обрез по `max_price` клиента.
- **`v3_guard_promise_mismatch`** — sanity-check «обещал товар → отдал карточки».
- **`noProgressBreak`** — safety-стоп против бесконечных циклов.

## 3. Новые/усиленные правила в `_shared/v3-tools/schemas.ts`

- **Rule 3c** — переписана: при `total=0` LLM сам делает второй поиск без гипотетических экспертных фильтров и сам говорит «расширил подборку».
- **Rule 10** — переписана: id только из текущего хода, без `_fresh_pool_ids`.
- **Rule 14** — переписана: при пустом пересечении LLM сам делает N коротких search_catalog по каждой оси и сам объединяет.
- **Rule 24** (новое) — не тащи фильтры из истории; маркеры «просто/только/без/давай теперь» = сброс старых модификаторов.
- **Rule 25** (новое) — partial-match без авторендера: при `partial_match=true` сначала честно признать unmatched_tokens.
- **Rule 26** (новое) — категория ТОЛЬКО из discover.
- **Rule 27** (новое) — обязательный render после успешного поиска: total≥1 → render_products в этом же ходу.

## 5. Оставшийся гэп

C08 и C23: `search_catalog` возвращает 3-5 валидных id, но LLM в финальном тексте пишет «не нашёл» вместо вызова `render_products`. Rule 27 это запрещает прямо, но модель его иногда игнорирует — видимо, не доверяет результатам, когда название карточки не содержит дословной фразы запроса.

**Рекомендация:** оставить как есть до следующего цикла наблюдения. Лечится либо ещё более жёсткой формулировкой rule 27 («даже если ты сомневаешься, что они подходят — покажи как “вот что нашлось, проверьте”»), либо переходом на более сильную модель для финального хода. Серверный nudge сюда возвращать НЕ предлагаю — это снова приведёт нас к «алгоритмическому мышлению», от которого мы избавлялись.

## 6. Ключевой кейс «лампа е27 теплая до 500 тенге» (C26)

До правок: серверный `v3_guard_no_intersection` подменял результат поиска и LLM крутился впустую.  
После правок (логи `qa20260629b_C26_warmlamp`):
1. discover_category «лампа» → 782 товара, 42 фасета.
2. LLM сам: `tip_cokolya=E27`, `cvetovaya_temperatura=[2700,3000]`, `max_price=500`, категория из discover → total=0.
3. LLM сам говорит «по точному сочетанию ничего нет, проверю без температуры» и делает второй search → 0.
4. Финальный текст: честный отказ с предложением ослабить условия.

Ровно то LLM-first поведение, которого мы добивались.
