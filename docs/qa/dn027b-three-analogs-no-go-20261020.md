Заказчик подтвердил: для сценария `customer-dn027b-analogs` минимум **три** аналога обязателен. Оракул `scripts/qa/customer-acceptance-cases-v2.json` не смягчён. ## Системный путь, не SKU-патч

1. В нормализованной технической схеме каталога разделить `mounting_cutout_mm` и `outer_diameter_mm`; не использовать общий «Диаметр» как прокси посадочного отверстия. Для отсутствующего поля — проверяемое обогащение из документации производителя с URL, идентификатором артикула и датой, а не догадка по названию. До наличия доказательства товар остаётся предварительным, не прямым аналогом.
2. Изменить структурную проверку **для класса встраиваемых замен**, чтобы подтверждённое посадочное отверстие было жёстким условием, а наружный диаметр — отдельной проверкой перекрытия/габаритов и явной оговоркой. Сохранить жёсткие проверки категории, типа монтажа, LED/цоколя, питания, IP, цены и положительного остатка. Не расширять молча критерии цвета/яркости.
   В [draft PR #119](https://github.com/siteelite-ai/clever-client-bot/pull/119), коммит `c91db2e9`, реализована opt-in проверка по подтверждённому монтажному вырезу и отделены предварительные различия мощности/яркости от жёстких монтажных условий. Старый маршрут не меняется. Локально прошли 1613 тестов shared/v3, 103 теста API, 305 тестов Node и типизация; оба GitHub CI-прогона для этого коммита завершились успешно. Это проверка кода, **не** прохождение клиентского сценария на живом каталоге. Production не менялся.
3. Добавить **типизированный слой проверенных характеристик производителя** с привязкой к точной живой карточке/артикулу: монтажный вырез (точный размер либо подтверждённый диапазон), внешний размер, 4000 K, форм-фактор, интерфейс лампы, наличие и тип драйвера, рабочий диапазон сетевого питания. Для IEK различающиеся или неопределённые фасеты можно согласовать только паспортом и проверкой отсутствия явных противоречий; «прочее» нельзя считать «нет», а разницу номиналов 220/230 В нельзя решать догадкой. Таблица должна быть закрыта от публичного доступа, хранить URL/версию источника и время проверки. После этой проверки всё равно нужен третий действительно близкий складской SKU; алгоритм не должен создавать товары.
   При обогащении хранить `color_temperature_k` и проверять конфликт с текстовым цветом каталога по документу изготовителя, а не считать «нейтральный» эквивалентом 4000 K. Для размеров нужны тип (круг/квадрат), единицы, URL производителя, артикул, дата и версия доказательства; при противоречии — fail-closed.
4. После данных: точечный preview-тест 3 раза, верификация страниц и артикулов, соседние регрессии других логических веток, затем только PR/production. Сейчас **NO-GO на выпуск как полностью готового продукта**.
