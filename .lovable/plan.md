## Проблема

Запрос «таблетка GX53 7Вт» → bridge синтезирует модификаторы `[таблетка, G, 53, 7, Вт]` вместо `[таблетка, GX53, 7Вт]`. Facet Matcher не получает цоколь и мощность как цельные значения → возвращает лампы 5.5 / 12 / 15 Вт.

Виновник — `supabase/functions/chat-consultant/index.ts:5839-5852`:

1. `replace(/([a-zA-Z])(\d)/g, '$1 $2')` режет `GX53 → GX 53`, `7Вт` остаётся как есть, но дальше...
2. `.split(/[×*хxХ]/i)` с флагом `/i` режет латинскую `X` внутри `GX53` → `G` + `53`.
3. `.replace(/([а-яА-ЯёЁ])([a-zA-Z])/g, '$1 $2')` режет `7Вт → 7 Вт`.

## Фикс (вариант 1, простой, data-agnostic)

В функции синтеза модификаторов (строки ~5836-5860):

1. **Pre-check «монолитная маркировка»** — для каждого `chunk` после split по пробелам/дефисам/слэшам/скобкам/запятым:
   - если `chunk.length ≤ 8` И содержит И буквы И цифры → считаем маркировкой → добавляем целиком (минус category), НЕ режем дальше;
   - иначе — старый путь (script-class boundaries + multiplier split).
2. **Из multiplier-split убрать латинские `x`/`X`**: `.split(/[×*хХ]/)` (без `/i`, без `x`).

Порог `≤ 8` покрывает: GX53, E27, T8, T75, IP44, BA15s, MR16, R7s, G4, 7Вт, 9Вт, 12В, 220В, 16А. Не покрывает длинные маркировки кабеля типа `ВВГнгLS3х2.5` — но они приходят отдельными чанками после первого split (пробел/дефис), а каждый под-чанк короткий.

## Файл и место

- `supabase/functions/chat-consultant/index.ts` — заменить тело цикла `for (const chunk of chunks) { ... }` (строки 5840-5860): добавить pre-check на монолитную маркировку перед текущим `subTokens = chunk.replace(...)...`.
