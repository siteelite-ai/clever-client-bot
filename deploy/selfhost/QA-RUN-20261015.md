# Isolated server3 release evidence — 2026-10-15

This is a gated test deployment, **not** a production cutover or an accepted
model-backed release. The original `chat-volt.testdevops.ru`,
`220volt.testdevops.ru`, Lovable project, hosted Supabase, and Transporter
connector were not switched to this stack.

## Passed without paid model requests

- Both new vhosts have valid HTTPS and remain behind site-specific HTTP 503
  maintenance gates. The two old test hosts returned HTTP 200 after the work.
- The pinned self-hosted Supabase preflight passed for 11 isolated services:
  only Envoy publishes `127.0.0.1:18081`; all other services have no host
  ports. The Edge container has no `OPENROUTER_API_KEY`, `VOLT220_API_TOKEN`,
  `CATALOG_API_TOKEN`, or `LOVABLE_API_KEY` environment fallback.
- Local tests: 54 passed, zero failed, two official-source-dependent tests
  skipped. This includes relay allowlist/streaming, the 17-route transform,
  isolated admin provisioning, admin-settings boundary, and Compose validation.
- The new `.225` relay is a separate Docker project. It publishes only
  `127.0.0.1:19084`; a request to `213.165.41.225:19084` from server3 failed
  as intended. The local health endpoint returned `{"status":"ok"}`.
  The existing `transporter-app-1` and `transporter-nginx-1` still run with
  their original ports.
- A separate `volt220relay` SSH account accepts only the new key from
  `45.86.39.77` and local forwarding to `127.0.0.1:19084`. The exact prior
  sshd configuration is backed up under
  `/var/lib/volt220-relay-ssh-operator/`; the installer checked `sshd -t`,
  the relay-user effective policy, and the unchanged root effective policy.
- The new server3 SSH sidecar passed its private-key, pinned-host-key,
  no-published-port, unprivileged-user, read-only-filesystem, and single-network
  checks. From a disposable container on `volt220test_internal`, the relay
  health endpoint returned `{"status":"ok"}` through the actual SSH tunnel.
- A reviewed private Edge source bundle was routed and staged separately. Its
  routed manifest SHA-256 is
  `e00aef5fa9bc7da7c47e801d3445690893098e5af58d781d7ef5a08b9f8eea27`.
  The new isolated Edge functions volume contains 15 routed chat URLs and two
  routed embedding URLs, and no direct OpenRouter endpoint URL. The Edge
  container reported `running` and `healthy` after recreation. The prior
  isolated functions volume was preserved as
  `functions.before-relay-20261015` alongside the current volume.
- A local synthetic-admin smoke passed for `admin-settings`: unauthenticated
  and foreign-origin requests were rejected, stored keys were represented
  only by presence flags, and direct REST access to key columns was denied.
  The real administrator provisioning script is installed root-only but has
  not been executed by the customer yet.

## Still required before opening either new public host

1. The customer sets a private password interactively to create the confirmed
   `info@st-lt.ru` test administrator and verifies login. Never send the
   password in chat or a command argument.
2. Create a **dedicated** OpenRouter key with its own dollar cap, plus a
   separate read-only catalogue token, and save both only in the isolated test
   settings. Their presence is currently false. The catalogue API exposes no
   known token-issuance endpoint, so its owner must provide the second token.
3. Make one bounded model-backed chat request through the new Edge function,
   verify a complete response, usage, and the request ID, then run a small
   catalogue product smoke. A successful anonymous `/models` GET does not prove
   a paid or keyed model request will work.
4. Recheck real admin login, public route/CORS negatives, and the old bot;
   only then remove the two **new-domain-only** 503 gates. Do not merge the
   draft self-hosting PR into production as part of this server release.

If a test fails, leave the new vhosts gated. The exact isolated relay/tunnel
Compose projects can be stopped independently. Restore only the saved
`functions.before-relay-20261015` directory if the isolated Edge bundle needs
rollback; never reset the database or touch the existing production services.
