# QA-матрица V7: безопасный ответ на «покажи» в BT-924

Исторические файлы V3 и V6 сохранены без изменений. Их SHA-256: `notion-legacy-bug-cases-v3.json` — `3e973d19352b03ea62d14a743393ac5f5ed07fda3ff00136ac4c7d02afdc0009`; `release-inventory-v6-20261019.json` — `b2ab45c808686b6a497053d1dd367f196576440ae4aa0ab9c7a225bcfe286591`.

В V3 сценарий `bt924-acti9-followup-show` требовал карточку после двух реплик: «Подбери аналог Schneider Acti9 C16» → «покажи». Это противоречило ограничению безопасности: обозначение C16 не подтверждает число полюсов исходного автомата. Реплика «покажи» не сообщает недостающий параметр. Нельзя считать подбор 1P проверенным лишь потому, что карточка другого товара содержит 1P/C/16A.

V4 (`notion-legacy-bug-cases-v4.json`, SHA-256 `882926735a6426bbfc3b560c2dddd82b8eb90a0803cec9bd1d597e1d558846ee`) сохраняет 32 ID, исходные формулировки и кратность прогонов V3. Только ожидания двух реплик BT-924 изменены: обе должны дать ноль карточек и видимое уточнение числа полюсов с серверными кнопками `1/2/3/4`. Третий ход `1` явно помечен `synthetic: true`: это тестовое нажатие ранее выданной сервером кнопки, **не** цитата заказчика и **не** запись браузерного действия. Лишь после него допускаются карточки с проверенными характеристиками на страницах каталога: 1 полюс, 16 А, характеристика C. Сценарий не утверждает совместимость или более низкую цену относительно исходного Acti9 без данных исходного артикула.

Точечная проверка на production зафиксирована в `docs/qa/reports/production-v499-bt924-first-two-20261020.json`: обе реплики завершились HTTP 200, выдали ноль карточек и видимый вопрос о числе полюсов с вариантами `2/3/1/4`. Серверный ключ этого каталожного признака — `kolichestvo_polyusov__polyuster_sany`, а не общий тестовый ключ `pole_count`. Поэтому два хода получили FAIL лишь по несовпадению имени слота. V4 теперь требует **точно наблюдавшийся** серверный ключ и связывает с ним третий синтетический ход. Это исправление оракула, а не ослабление: ноль карточек до ответа, вопрос о полюсах, четыре кнопки, точный предыдущий чип и проверка 1P/C/16A по карточкам остались обязательными.

Отдельный трёхходовый узкий прогон `docs/qa/reports/production-v499-bt924-three-turn-20261020.json` прошёл: первые два хода без карточек, после тестового чипа `1` — четыре названия 1P/C/16A и оговорка о неподтверждённой взаимозаменяемости. Этот прогон проверял поток ответов и названия; страницы товаров он **не** открывал и не доказывает строгую V7-проверку свойств каждого товара либо всю матрицу.
