name: V3 Criteria Reasoning (Слой 5 — рассуждение модели = истина)
description: Сервер выравнивает оператор критерия по прозе модели («больше 12 мм»), а не по сырому числу из реплики клиента; поддержано строгое неравенство exclusive.
type: feature

Проблема: клиент называет число своей детали (12 мм), модель вслух правильно рассуждает
(«нужен диаметр больше 12 мм»), но в `criteria[]` присылает `op:"eq", value:12` — потому что
12 это число из чата. Гейт (Слой 2) прозу не читает, `eq 12` проходит, и клиент видит ровно то,
что модель сама назвала неподходящим. Слой 4 не срабатывает: 12 не меньше 12.

Принцип (по требованию пользователя): **истина — рассуждение AI, а не сырое число клиента.**
Направление подбора берётся из прозы модели; порог сервером не выдумывается.
Строгость также определяется только буквальной формулировкой AI: «больше/меньше» = `>`/`<`,
«не меньше/не больше» = `≥`/`≤`. Совпадение порога с числом клиента само по себе никогда
не делает неравенство строгим и не меняет оператор.

Реализация (`_shared/v3-tools/criteria-reasoning.ts`, чисто, data-agnostic):
- `extractReasoningBounds(text)` — направленные числовые утверждения из прозы:
  `не менее/от/минимум` → min inclusive, `больше/более/свыше` → min **strict**,
  `не более/до/максимум` → max inclusive, `меньше/менее/ниже` → max strict.
  Отрицательные формы имеют приоритет (lookbehind `(?<!не\s)`), числа без единицы игнорируются.
- `alignCriteriaWithReasoning(criteria, reasoningText)` — для критериев уровня A с совпадающими
  единицей И числом переписывает `op` (+ `exclusive`) по прозе. Без совпадения числа порог не
  меняется — сервер не выдумывает величины. Уровень B не трогается.
- `Criterion.exclusive?: boolean` в `criteria-gate.ts`: `checkCriterion` для strict min требует
  `got.max > value`, для strict max — `got.min < value`; `buildCriteriaQuery` пишет «больше/меньше».
- Оркестратор: Слой 5 применяется ДО Слоя 4, лог-шаг `v3_guard_criteria_reasoning_aligned`
  (meta.alignments). Проза за ход собирается в `assistantReasoning` (включая заглушённые фрагменты).

Разрешение конфликтов формулировок (fd817c18): модель повторяет одно требование по-разному
(«больше 12 мм», затем «≥ 12 мм», «от 12 мм»), и раньше побеждала формулировка, которая раньше
попалась парсеру → strict терялся, трубка 12/6 проходила гейт.
- `collapseBounds(bounds)` — группировка по `unit|value|op`, `strict = OR` по группе: строгая
  формулировка не размывается последующими нестрогими.
- Несколько направлений по одному числу («до усадки больше 12», «после усадки меньше 12») —
  направление берём из машинного `op` модели, из прозы только строгость. Если машинный `op`
  не совпал ни с одним направлением, критерий не трогаем и логируем
  `v3_guard_criteria_reasoning_ambiguous` (meta.bounds).

Флаг: тот же `app_settings.v3_criteria_gate_enabled`. Тесты: `criteria-reasoning_test.ts` (9), всего 47.
