## Cleanup and security caveat

- Both temporary test `app_settings` key columns were set back to NULL
  immediately after the third check, and a DB read verified `NULL|NULL`.
- The one-time private GPG directory was removed from server3; the temporary
  importer and paid-smoke helper were removed. The now-unneeded automatic
  revocation timer was stopped after verifying the NULL state. The public SQL
  editor contains only public key text and encrypted output. No production
  key was rotated in this run.
- NULL does **not** guarantee erasure from PostgreSQL WAL or backups. Before
  treating server3 as a long-lived public deployment, rotate those two working
  keys in a controlled manner and use separate least-privilege test keys.
- The existing Settings page currently loads raw `app_settings` keys into
  browser state and calls OpenRouter from the browser for ping tests. Do not
  open Settings while shared working keys are present on a test DB; the page
  needs a server-side, masked/replace-only secrets flow before a full cutover.
