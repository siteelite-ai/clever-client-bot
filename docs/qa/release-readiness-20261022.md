SHA bundle и такая сверка **не доказывают сами по себе** происхождение удалённой сборки из Git-коммита; контроль основан также на зафиксированном операторском деплое только V3 preview и его локальном rollback backup.

## Что мешает полному выпуску

1. **Закрытая live-приёмка `NOT_RUN`**: сохранённый Supabase PAT относится к роли Developer; запись Edge Secrets возвращает 403. Нужен Owner/Admin с правом записи секретов или безопасная выдача двух отдельных временных QA-секретов. Не отключать JWT и приватный admission ради теста. После этого — бесплатный preflight фактического аутентифицированного каталога, 15 route-only проб, затем точечные сценарии и V9 (190 прогонов / 280 ходов), дополнительный area/shape и браузерные регрессии. Локальная ссылка на уже имеющийся `jsdom` восстановлена без изменения lockfile; `run-customer-acceptance.mjs --help` стартует, но это не живой прогон. У раннера нет долларового лимита: контролировать расход внешним лимитом OpenRouter и фактическим usage. Публичная ошибка `220volt.testdevops.ru/api/categories` без каталожного токена не доказывает отказ рабочего `220volt.kz/api`.
2. **DN027B `0/3` доказанных прямых аналогов** в рабочем каталоге. Есть два технически перспективных кандидата, но текущие цена/остаток, единица продажи и все заводские оси не подтверждены; третий прямой складской SKU не установлен. Свежая публичная карточка Navigator 94833 показывает «Под заказ», хотя старый поисковый индекс ошибочно указывал остатки; 94834 теперь перенаправляет на общий каталог. Порог «три» заказчик оставил обязательным. Нельзя объявлять PASS с предварительными или условными заменами. См. [issue #124](https://github.com/siteelite-ai/clever-client-bot/issues/124).
3. **Публичная защита `NOT_READY`**: draft per-subject admission по умолчанию OFF. Нет подтверждённого исходника/deploy control действующего Cloudflare Worker и независимого доверенного issuer для холодного прямого browser fallback. Нельзя включать enforce ценой отказа работающего маршрута или оставлять обход без отдельного решения о риске. См. [issue #126](https://github.com/siteelite-ai/clever-client-bot/issues/126).
4. **Публикация/откат**: после выполнения первых трёх пунктов нужны проверка exact-head CI, staged merge/deploy, сверка загрузчика и версии виджета на `220volt.testdevops.ru`, точечный браузерный smoke, мониторинг ошибок и **испытанный** откат каждого изменённого runtime-компонента. Копии текущих Edge body/source и JS-ассетов уже сохранены; но обратная публикация Lovable, восстановление Edge из этих копий на изолированной цели и совместимость шести additive SQL-миграций со старым runtime ещё не доказаны. Git revert сам по себе не откатывает задеплоенную Edge Function или Lovable-публикацию; для SQL нельзя автоматически применять разрушительный `down`.

**Оценка срока:** после получения прав на закрытый QA, подтверждённых трёх рабочих SKU и решения о защите холодного резервного маршрута — ориентир два–три рабочих дня на live-прогоны, исправление найденного, выпуск и финальный smoke, если проверки не откроют новых дефектов. До выполнения внешних условий календарную дату полного релиза достоверно назвать нельзя. Текущий продукт можно продолжать использовать в прежней публичной версии; черновик не следует представлять заказчику как опубликованное исправление.
