## Оси оценки (для каждого кейса)

1. **Tool-flow** — какие тулы вызваны в каком порядке (из `chat_request_logs.steps`).
2. **Render correctness** — карточки реально соответствуют запросу (URL открываем через Playwright и сверяем).
3. **Honesty** — если чего-то нет, сказано честно, без подмены признака.
4. **Anti-hallucination** — нет URL/цен в тексте вне карточек.
5. **UX** — не больше 1 первого пузыря до тула, не больше 1 финального пузыря после рендера.
6. **KB / контакты** — для C12 (диагностика) ожидаем `lookup_knowledge`, не подбор товара.

## Ожидаемые ветки по типам

- **Подбор по типу** (C04, C05, C07, C13, C14, C15, C19, C20, C22, C23, C24, C25): `discover_category → search_catalog by_filter → render_products`.
- **Аналог по якорю** (C01, C03, C06, C16, C21): `search_catalog by_article|by_pagetitle (anchor) → discover_category → search_catalog by_filter с anchor_leaf_category → render_products`.
- **Вопрос про конкретный товар** (C02): `search_catalog by_article → короткий текстовый ответ из short_traits + render_products как пруф`.
- **Жаргон** (C04 «кукуруза», C11 «КГ»): сначала `discover_category`; при category_not_found — `jargon_recover_catalog`; затем по обычному пути.
- **Замена в категории без якоря** (C08 «заменить освещение»): `discover_category → search_catalog`.
- **Подбор по применению/задаче** (C09 насос, C10 двигатель, C22 кондиционер, C23 земля, C25 парковка): LLM сам как эксперт выводит параметры → стандартный flow.
- **Диагностика без товара** (C12 «выбивает автомат»): `lookup_knowledge` или чисто текстовый экспертный ответ; товары не обязательны.
- **Дешёвый/потолок** (C01 «не дороже 1000тг», C17 «самый дешёвый», C21 «подешевле»): `sort_cheapest` + `max_price`.
- **«Все позиции»** (C18 «покажи все позиции»): `search_catalog by_filter` с большим per_page, без sort.
