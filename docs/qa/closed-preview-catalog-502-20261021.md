# Закрытый preview: отказ каталога на сценарии гостиной 30 м²

21.10.2026 (МСК) выполнен **один** четырёхходовый запуск `customer-chandelier-30m2` против закрытой функции `chat-consultant-v3-closure-preview`. Машинный отчёт: [closed-preview-chandelier-origin-20261021.json](reports/closed-preview-chandelier-origin-20261021.json). Сценарий завершился `FAIL`: 4/4 хода записаны, но ожидаемые товары не получены на 1-м и 4-м ходах; страницы товаров не проверялись.

По `public.chat_request_logs.steps` в Supabase, прочитанным по точным ID без обращения к боту:

| Ход, ID | Проверенное наблюдение |
| --- | --- |
| 1, `aac3cd2e-e61a-45c7-ba4b-245b67e36ad6` | Оба вызова `discover_category` содержат `result.message: "categories returned HTTP 502"` (исходный запрос и повтор с «люстра»). |
| 4, `0fcb1861-f91c-4ca1-9469-421fd99cb773` | Первый `discover_category` содержит `result.message: "categories returned HTTP 502"`; второй завершился `category_not_found`, не HTTP-ответом каталога. |

В текущем обработчике `discover-category.ts` сообщение `categories returned HTTP 502` формируется после фактического non-OK ответа `fetch` к настроенному upstream `/categories`. Следовательно, Edge-функция получила **реальный HTTP 502 от каталожного endpoint** до поиска товаров и до коррекции числового параметра моделью. Источник 502 за каталожным proxy/gateway не установлен. Одно лишь общее имя ошибки `transport_5xx` не было бы таким доказательством: этим кодом сейчас обозначаются и некоторые 4xx; вывод выше основан именно на сохранённом `result.message`.

Два старых production-сбоя на этапе `v3_product_measurement_correction_failed` этим запуском **не воспроизведены и не объяснены**. Их `upstream_origin` остаётся неизвестным. Для повторной проверки этого этапа сначала нужен доступный `/categories`; затем достаточно одного адресного четырёхходового прогона, без массового расхода OpenRouter.

Для доступа на время проверки создавался отдельный `VOLT220_V3_PREVIEW_SECRET`: после теста он удалён, отсутствие подтверждено списком секретов. Установка и удаление подняли конфигурационные версии production/preview до v574/v172, но bundle SHA-256 production сохранился `3ef4a7c24b1ec22e5f1504f127de8e8d39c5696be3f28d68bd8ac8e8291f47f0`; функция `ACTIVE`, бесплатный `OPTIONS` вернул HTTP 200. Код production и виджет не публиковались. Это проверка доступности, не доказательство исправного товарного ответа.

**Решение для выпуска: NO-GO.** Сначала подтвердить устранение HTTP 502 у каталожного `/categories`, затем повторить адресный сценарий и отдельные регрессии. Не подменять сетевой отказ сообщением «товаров нет» и не ослаблять требование клиента о трёх проверенных аналогах DN027B.
