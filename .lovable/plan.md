## Цель

Classifier перестаёт «семантически фильтровать» слова из запроса. Любой токен, который не входит в `product_category` и не является грамматической обёрткой (междометия, частицы, вежливые формы, глаголы запроса), ОБЯЗАН попасть в `search_modifiers`. Никаких примеров товарных категорий, никаких whitelist слов — только структурное правило.

Это решает кейс «найди лампы початки» (и любой будущий жаргон) системно: незнакомое слово сохраняется → точечный поиск даёт 0 → срабатывает существующий jargon-fallback.

## Правка (1 файл)

**`supabase/functions/_shared/classifier-prompt.ts`** — секция `search_modifiers` (строки 62-69):

Заменить текущую формулировку «ВСЕ значимые слова… со смыслом» на чисто механическое правило:

```
search_modifiers = МЕХАНИЧЕСКИ собранный список:
  1. Токенизируй исходный запрос (split по пробелам и знакам препинания, кроме дефиса/точки/запятой внутри маркировок).
  2. Удали токены, входящие в product_category.
  3. Удали ТОЛЬКО грамматическую обёртку: глаголы запроса (найди/покажи/подскажи/хочу/нужен/есть/посоветуй),
     вопросительные частицы (ли, же, ну, вот), междометия, вежливые формы (пожалуйста, спасибо).
  4. ВСЁ остальное → search_modifiers, по одному токену на элемент.

ЗАПРЕЩЕНО:
  - Решать, что токен «не похож на атрибут товара» и выкидывать его.
  - Объединять несколько токенов в один элемент массива (кроме случая is_replacement, см. выше).
  - Нормализовать/переводить/исправлять опечатки.

Самопроверка перед возвратом JSON:
  N_input  = число токенов запроса
  N_cat    = число токенов в product_category
  N_wrap   = число удалённых обёрточных токенов
  Должно выполняться: len(search_modifiers) == N_input - N_cat - N_wrap
  Если не сходится — ты выкинул токен, верни его обратно.
```

Секция `critical_modifiers` остаётся как есть (подмножество, выбираемое по смягчающим словам).

## Что НЕ меняем

- Код классификатора, QFv2, jargon-fallback, Facet Matcher — без изменений
- Шаг A (определение обёртки/intent) — без изменений
- Структура JSON-ответа — без изменений
