name: V3 Criteria Strict Threshold (Слой 4b — порог = число клиента → строгое неравенство)
description: op=min/max со значением, равным числу клиента в той же единице, автоматически становится строгим (exclusive) — граница исключается.
type: feature
---
Проблема: Слой 5 берёт строгость только из прозы модели. Если модель сама формулирует
требование нестрого («внутренний диаметр ≥ 12 мм» для кабеля 12 мм), строгость взять негде —
и трубка 12/6 честно проходит гейт (сессия 20df00f9).

Правило (data-agnostic, `_shared/v3-tools/criteria-consistency.ts`):
`enforceStrictClientThresholds(criteria, clientText)` — для критериев уровня A с `op:min|max`
и числовым value: если value совпадает с числом клиента той же единицы, ставится `exclusive:true`.
Обоснование: `min/max` по контракту означает ПОРОГ (габарит товара должен охватить/пройти объект
клиента), равенство порогу физически бессмысленно — нужен зазор. Числа-характеристики товара
приходят с `op:eq` и не трогаются.

Оркестратор: Слой 4b после Слоёв 5 и 4, лог-шаг `v3_guard_criteria_strict_threshold`
(meta.tightened). Промпт `<criteria_contract>`: порог из размера объекта клиента формулируется
строго («больше X»), чтобы проза совпадала с машинной проверкой.

Флаг: тот же `app_settings.v3_criteria_gate_enabled`. Тесты: 50.
