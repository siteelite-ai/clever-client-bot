# Аварийный точный поиск при сбое категорий — черновик

Статус на 21.10.2026: код подготовлен только в draft PR. В production он не опубликован; серверный флаг `VOLT220_TAXONOMY_OUTAGE_EXACT_LOOKUP_ENABLED` по умолчанию выключен. Это не закрывает инцидент каталога [#123](https://github.com/siteelite-ai/clever-client-bot/issues/123) и не меняет статус приёмки V9 (`NOT_RUN`).

При включённом флаге только подтверждённый ответ `/categories` HTTP 5xx допускает **один** дополнительный GET `/products` по единственному точному артикулу или маркировке из сообщения клиента. Для маркировки дополнительно нужен указанный клиентом тип товара, совпадающий с названием и листовой категорией карточки. Цена, положительное складское свидетельство, единственность товара и полнота поискового окна обязательны. Запросы с другими неразобранными условиями, поиск аналогов, ошибки 401/403/404, 429 и тайм-ауты завершаются техническим сообщением без дополнительного поиска. Отсутствие товара не утверждается по сетевой ошибке.

Проверка до публикации: `deno check` прошёл; 1 784 офлайн-теста серверной логики и 18 тестов матрицы V9 прошли; `git diff --check` чист. В мокированных сквозных тестах проверены одиночный HTTP-запрос, неверный артикул, аксессуар вместо товара, чужая категория, непроверяемый размер, отказ `/products`, ошибки доступа/лимита, порядок событий SSE и неизменность маршрута при выключенном флаге. Это **не** живая проверка авторизованного каталога и не доказательство качества всех клиентских запросов.

Перед включением в preview требуется отдельно проверить UX аварийного сообщения и точной карточки на том же API, который использует V3. Если поведение нежелательно, флаг остаётся выключенным либо его можно убрать без отката остальных исправлений. Полный выпуск нельзя считать готовым, пока не устранён сбой каталога и не подтверждены три совместимых складских аналога DN027B ([#124](https://github.com/siteelite-ai/clever-client-bot/issues/124)).
