# Separate test Supabase on server3 (not a production cutover)

This directory contains **only** a defensive overlay and read-only preflight
for the official Supabase Docker release. It does not include credentials,
database data, or a fork of Supabase. Do not point the existing 220volt widget,
MODX, old cabinet, or production Supabase project at this stack.

## Exact upstream source

- Official tag: `self-hosted/v0.8.2` (2026-09-23).
- Annotated tag object: `47111f95a43ffcc20ab288e29c48ce0b80174bd6`.
- Peeled source commit: `564eab8ad7840b13324f68b1bfac074ef8d51c21`.
- SHA-256 of `docker/docker-compose.yml`:
  `8ba18fd43e9afba90e8287c8e8afc4bdda1e38d2228e57ff660968bb550da054`.

Use the dedicated root-owned directory
`/var/lib/volt220-test-supabase/upstream` on server3. Run the commands below
from a restricted root shell; `/opt` is on the small root filesystem and must
not hold this stack's bind-mounted DB/Storage data. Clone by the exact tag,
check the commit and hash, then prepare the official `docker/.env` **on
server3 only**. Never use the official one-line install or copy a production
project's database, Auth users, keys, Storage, or secrets.

```sh
install -d -m 0700 -o root -g root /var/lib/volt220-test-supabase
git clone --depth 1 --filter=blob:none --sparse --branch self-hosted/v0.8.2 \
  https://github.com/supabase/supabase /var/lib/volt220-test-supabase/upstream
git -C /var/lib/volt220-test-supabase/upstream sparse-checkout set docker
git -C /var/lib/volt220-test-supabase/upstream rev-parse HEAD
sha256sum /var/lib/volt220-test-supabase/upstream/docker/docker-compose.yml
```

The two printed checksums must match the values above before any deployment.
The official source must remain immutable; upgrade in a reviewed separate
release, not via `git pull` on the running copy.

## Private environment

Run the one-time initializer from a restricted root shell. It verifies the
official release and the hashes of the two upstream key generators, then
reproduces their cryptographic output in one Node process. It creates the
root-only `docker/.env` with `0600` permissions **without printing keys**,
changing the pinned `docker-compose.yml`, or making an `.old` backup. It
refuses to overwrite an existing `.env` or `.env.old`.

```sh
node /path/to/repo/deploy/selfhost/init-private-env.mjs \
  --upstream /var/lib/volt220-test-supabase/upstream
```

Do **not** run official `generate-keys.sh --update-env` or
`add-new-auth-keys.sh --update-env` on this checkout. The latter edits the
pinned Compose file as well as `.env`, breaking the source hash and leaving a
`.old` file; both scripts also print secret values. The overlay explicitly
enables the Auth, Realtime, Storage, and Edge Runtime JWT/JWKS settings which
that script would otherwise uncomment in the base file. The non-secret
settings generated by the helper are listed in
[`settings.example`](./settings.example). Use independent test-only Postgres,
JWT, dashboard, and API keys; no production Supabase credentials. Any external
catalogue or OpenRouter key for test traffic needs a separate scope/cost review.

Keep `.env`, `.env.old`, database/storage bind mounts, and backups outside Git
with server-only permissions. Creating the first admin account and schema is a
separate reviewed step. Public sign-up, phone sign-up and anonymous users stay
disabled. Configure SMTP only if invitations/password reset are required.

The official `FUNCTIONS_VERIFY_JWT` switch is global. This test configuration
sets it to `false` for public `chat-consultant-v3` with a publishable key.
Before lifting HTTP 503, copy **only** reviewed `chat-consultant-v3`,
`admin-users`, `knowledge-process`, and required `_shared` code, then verify
that the latter two enforce their own admin authentication. Do not blindly
copy other unauthenticated preview/closure functions into this public stack.
The official checkout contains a sample `volumes/functions/hello` endpoint;
remove it from the served function directory before opening the API, after
confirming the exact path in the isolated checkout. Keep the official
`volumes/functions/main` router.
For the initial release, `SELFHOST_TEST_MODE=true` and
`KNOWLEDGE_REMOTE_IMPORT_ENABLED=false` disable URL/sitemap imports until an
egress/DNS-rebinding defense is reviewed. Lovable failover and preview are
disabled, and `LOVABLE_API_KEY` must not be copied; legacy PDF processing
should fail closed without that key.

Before adding any test OpenRouter key, apply and check the admission-control
RPC against the isolated test DB. Public chat runs in `enforce` mode with at
most 3 admissions/minute and 2 in-flight requests. These limits protect
concurrency but **do not** replace an independent dollar cap on the test
OpenRouter key. Keep the API maintenance gate until both are verified.

## Safe Compose boundary

Pass the official base **first** and `docker-compose.test.yml` **second**.
Compose `!override` needs version 2.24.4 or newer (server3 had 5.5.1 when
checked). A normal list merge would leave the upstream public port open; this
overlay deliberately replaces the list. The only host binding is Envoy API
gateway at `127.0.0.1:18081`. Supavisor/Postgres, Studio, Edge Runtime and
other services have **no host ports**. The isolated Compose project is
`volt220test`, with network `volt220test_internal` and project-scoped named
volumes. Bind-mounted DB/Storage files live under
`/var/lib/volt220-test-supabase/upstream/docker/volumes/db/data` and
`/var/lib/volt220-test-supabase/upstream/docker/volumes/storage`, not under
`/opt` or any existing application directory. `realtime-dev.` remains the
Realtime tenant-name prefix required by the official configuration.

Run the read-only preflight before **every** start or configuration update:

```sh
node /path/to/repo/deploy/selfhost/validate-compose.mjs \
  --upstream /var/lib/volt220-test-supabase/upstream \
  --env /var/lib/volt220-test-supabase/upstream/docker/.env
```

It verifies the pinned source, private settings and permissions, the **rendered**
Compose model (without printing its secrets), resource limits, loopback-only
gateway, absence of all other host ports, and existing Docker name/network/
volume collisions. A failed preflight means **do not start**. `--offline` may
be used for local static review only; it skips host collision checks and is
not sufficient for server release.

If and only if release review approves, use a clean shell environment to
prevent inherited production variables from overriding `.env`:

```sh
cd /var/lib/volt220-test-supabase/upstream/docker
env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin \
  HOME="$HOME" docker compose --project-name volt220test --env-file .env \
  -f docker-compose.yml -f /path/to/repo/deploy/selfhost/docker-compose.test.yml \
  up -d --wait
```

Do not run `reset.sh`, `docker compose down -v`, or any command that removes
volumes on a server with user data. Stopping the test project must preserve
its volumes, and rollback must leave the existing website/production Supabase
untouched.

## Public API and HTTPS

`api-volt-next.testdevops.ru` must have a valid TLS certificate before browser
traffic is allowed. The host Nginx should proxy **only** the required API
prefixes (`/auth/v1/`, `/rest/v1/`, `/functions/v1/`, `/storage/v1/`, and
`/realtime/v1/`) to `127.0.0.1:18081`, with WebSocket upgrade support for
Realtime. Do **not** proxy `/` or Studio/admin routes to the public Internet.
For test admin operations, use a restricted SSH tunnel to the loopback gateway
or a separately authenticated internal path. The React customer cabinet at
`chat-volt-next.testdevops.ru` is a different service from Supabase Studio.

Do not lift the maintenance gate on the new cabinet/API until the test schema,
test credentials, function secrets, TLS, CORS, and frontend build are all
verified to reference this isolated instance only.
