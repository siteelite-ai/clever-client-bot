---
name: V3 system prompt is data-agnostic
description: Запрет на доменные примеры (категории/бренды/артикулы/жаргон 220volt) в системном промпте V3-агента
type: constraint
---
**Системный промпт V3 (`supabase/functions/_shared/v3-tools/schemas.ts`) — БЕЗ доменных примеров.** Тот же запрет, что и для spec (§0): ZERO примеров с реальными категориями, брендами, артикулами, кодами серий, фасет-ключами и жаргоном 220volt. Никаких «Лампы светодиодные», «GX53», «ECO T75 IEK», «IEK», «tip_cokolya», «Светильники встраиваемые», «X-100», «Кабель ВВГ», «УЗО» и т.п. в шаблонах GOOD/BAD, инвариантах, fallback-правилах.

**Почему:** примеры с конкретикой превращают агента в кейс-парротер (заучивает кейс лампы вместо общего принципа), ломают переносимость промпта на другой каталог и нарушают Core §0.

**Как формулировать вместо примеров:**
- Абстрактные плейсхолдеры: L₀ (листовая категория якоря), A/B-оси (критические подкатегорийные / главный технический), V (вендор), S (код серии), вторичные параметры.
- Текстовые инварианты без иллюстраций («category_in = листовая категория якоря, не ослабляется на fallback»).
- Шаблоны GOOD/BAD пишутся через те же плейсхолдеры, без конкретных значений из каталога.

**Где можно конкретику:** только в коде (`index.ts` — параметризованная логика по `short_traits`/`vendor`/`category` карточки) и в тест-фикстурах. В системном промпте — никогда.
