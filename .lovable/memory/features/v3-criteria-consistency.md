name: V3 Criteria Consistency (Слой 4 — числа клиента неприкосновенны)
description: Сервер не даёт модели тихо ослабить порог ниже числа, названного клиентом; понижение автоматически возвращается к исходному.
type: feature
---
Проблема: гейт (Слой 2) проверяет карточки против критериев, которые прислала модель.
Модель могла тихо снизить требование клиента до того, что есть в каталоге (клиент — 200 мм,
модель — `op:min value:40`), и гейт честно пропускал карточки. Ни один слой это не ловил.

Реализация (`_shared/v3-tools/criteria-consistency.ts`, чисто, data-agnostic):
- `extractClientQuantities(text)` — пары (число, единица) из реплики клиента; числа без единицы игнорируются.
- `findUnderstatedCriteria(criteria, clientText)` — критерии уровня A с той же единицей: `min` не ниже
  максимального клиентского числа, `max` не выше минимального, `range` — по верхней границе.
- `correctCriteria` — порог поднимается до клиентского; оркестратор считает гейт уже по исправленным
  критериям. Лог-шаг `v3_guard_criteria_understated` (meta.violations).
- Промпт `<criteria_contract>`: число клиента неприкосновенно, подмена на удобный порог запрещена,
  при непокрытии каталогом — честный ответ + контакты.

Сопутствующий фикс гейта: `op:min|max` со **строковым** value больше не деградирует в строгое равенство
(`checkCriterion`, тест «op=min со строковым value»).

Абортный/таймаутный фолбэк V3 больше не говорит «переформулируйте»: честно сообщает, что под названные
требования позиции не нашлось, и направляет к менеджеру.

Флаг: тот же `app_settings.v3_criteria_gate_enabled`.
