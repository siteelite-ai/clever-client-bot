# Матрица приёмки V9: строгий запас термоусадки

Заказчик 20.10.2026 выбрал обязательное правило для подбора трубки **на кабель**: внутренний диаметр до усадки не меньше `1,20 × D кабеля`, после усадки — строго меньше `D кабеля`. Поэтому для Ø12 мм границы `≥14,4` и `<12` исключают 14/7, а для Ø10 мм границы `≥12` и `<10` допускают 12/6. Это решение уточняет противоречивый пример BT-929; см. [запись решения](heat-shrink-20pct-decision-20261020.md).

V9 содержит две новые версии наборов сценариев:

| Набор | Предыдущий SHA-256 | Новый SHA-256 | Изменение |
| --- | --- | --- | --- |
| `customer-acceptance-cases-v2.json` | `549600818c83cb1813d05bba2e32316f71b42059596c973d5b814356d129b366` | `6fb6646ba9f5bf8d612e6aa4c707d2954ad351be6a9a2f43b7cf9239a020c7e7` | Только критерии Ø12 мм и ТТУ Ø10 мм. |
| `notion-legacy-bug-cases-v6.json` | `f4ba64271c02cdbc7549be3061dc0171952fae8ac6555d2bba67d896209a1e61` | `c45ef36b7bd713f003bfa4a46f2530f8e25b528947eb198f7f5243ff23a6f737` | Только критерий BT-929 Ø12 мм. |

Во всех трёх сценариях проверяются два независимых слоя: числовые характеристики **каждой живой карточки каталога** и машинный `selection_contract.mandatory_criteria`. Для Ø12 мм контракт должен содержать `min 14.4`, `exclusive: false` и `max 12`, `exclusive: true`; для Ø10 мм — `min 12`, `exclusive: false` и `max 10`, `exclusive: true`. Проверка нового контракта связывает оператор, число и включённость границы **с одним и тем же ключом**. Старый поиск разрозненных строк в JSON мог давать ложный PASS.

Остальные два набора сценариев и файл сентябрьских вариаций, все исходные формулировки запросов, повторы, синтетические пометки и остальные ожидания сохранены. Исторические `customer-acceptance-cases.json`, `notion-legacy-bug-cases-v5.json`, [реестр V8](release-inventory-v8-20261020.json) (SHA-256 `d41603654570985dc055fd2b82354604bcf903740329983ba66dd91e6f069ecd`) и прежние отчёты не переписаны. Для новых правил созданы [реестр V9](release-inventory-v9-20261020.json) и отдельные закреплённые хеши. Его объём — 5 файлов, 190 прогонов, 280 ходов; статус всей матрицы — **NOT_RUN**. Два ранее успешных точечных запроса на термоусадку не засчитываются за полную матрицу.

В точечном production-ответе, сохранённом локально 20.10.2026, карточки и видимый текст уже удовлетворяли запасу 20%, но `mandatory_criteria` содержал старый нижний предел `>12` для кабеля Ø12 мм и `>10` для Ø10 мм. Это **известное расхождение**, а не прохождение V9. До исправления формирования контракта и повторного строгого прогона результат V9 нельзя обозначать PASS. Также V9 не доказывает прохождение других клиентских сценариев, в том числе подбора аналогов DN027B: они требуют собственной живой проверки.

Офлайн-проверки: `node scripts/qa/build-release-ledger-v9.mjs --check` и `node --test scripts/qa/build-release-ledger-v9.test.mjs`. Строгие живые прогоны выполняются отдельно для каждого из четырёх файлов сценариев; для сентябрьского набора обязателен файл вариаций. Каждый запуск должен явно задавать `--endpoint`, `--strict-full-suite` и сохранять новый отчёт. Исторические отчёты нельзя присоединять к V9 по имени сценария или похожему ответу.
