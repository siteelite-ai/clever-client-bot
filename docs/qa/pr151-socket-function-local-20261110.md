# PR151: назначение розеток, локальная проверка

## Причина

Лексическая проверка целевого класса «розетка» сама по себе не отличает силовую розетку от RJ-45, телефонной или TV-розетки. Общая категория «Розетки», совпадение цвета и скрытого монтажа также не доказывают нужное назначение. Поэтому интернет-розетка могла пройти прежние независимые проверки.

## Изменение

В общий контракт проверки карточек V3 добавлен дополнительный серверный фильтр назначения (`socket-function-contract.ts`). Он применяется через `scopedVisibleRequestContract`, то есть не привязан к одному запросу, SKU, серии или цвету и действует также при резервном подборе.

- Для обычного подбора розеток положительно распознанные RJ-45/компьютерные, телефонные, антенные/TV и USB-only изделия не подменяют силовые розетки.
- Явно запрошенный информационный интерфейс остаётся доступным. Компьютерная, телефонная, TV и USB — не взаимозаменяемые назначения; общий явно запрошенный информационный класс допускает соответствующие сигнальные интерфейсы.
- Назначение берётся из текущей реплики и подтверждённой серверной истории. Изменение цвета или количества его не стирает. Явное новое назначение заменяет предыдущее.
- Класс карточки устанавливается по её названию и положительным характеристикам типа/интерфейса, не по рассуждениям модели, бренду или произвольному описанию совместимости. Отсутствующие USB-порты не превращают силовую розетку в USB-only.
- Комбинированное изделие допускается только при независимых признаках силовой части в той же карточке. Заземление экрана RJ-45 само по себе не доказывает силовую часть.
- Новый фильтр только исключает конфликтующие карточки. Проверки целевого класса, цвета, монтажа, серии, количества, цены и наличия не удаляются и не получают обхода через «эквивалентность признака».

Это не новая инженерная гарантия: если назначение вообще не раскрыто источником, фильтр не выдумывает его. Сохраняются прежние проверки такой карточки; положительно установленный иной интерфейс больше нельзя игнорировать.

## Совместимость и диагностика

Серверный шаг `v3_socket_function_contract_compiled` фиксирует выбранное назначение. Отказы учитываются общей проверкой видимого контракта. Неявное правило обычной розетки не выдаётся за явно названный клиентом фасет: формат публичного `selection_contract` прежних корректных карточек не изменён. Контрольный SHA-256 старого OFF transport probe сохранён без обновления эталона.
