# План: два независимых фикса за feature-flags

Оба кейса ломаются на одном гварде `no_progress_break`, но причины разные. Делаем **два независимых флага**, чтобы можно было включать/выключать по отдельности и откатывать мгновенно.

## Этап 1 — миграция (флаги в `app_settings`)

Добавляем две булевы колонки, обе `default false`:

- `v3_anchor_filter_enabled` — серверная фильтрация якоря из результатов (кейс кабеля).
- `v3_relaxation_hints_enabled` — усиленные подсказки по релаксации фильтров в промпте (кейс светильников).

Обе выключены по умолчанию — прод продолжает работать как сейчас, пока не переключим вручную.

## Этап 2 — Anchor filter (кейс кабеля КГтп)

**Файл:** `supabase/functions/chat-consultant-v3/index.ts` (и/или тонкий helper рядом).

**Логика (только при `v3_anchor_filter_enabled = true`):**
1. Когда LLM в режиме «аналог» вызывает `search_catalog` после того, как якорь уже найден (id известен из предыдущего `by_article`/`by_pagetitle`), — перехватываем результат перед передачей в модель.
2. Отфильтровываем из `results` товар с id якоря. Пересчитываем `total` соответственно (`total - 1`, минимум 0).
3. Добавляем в ответ tool'а `warning: "anchor_excluded:<id>"` — для наблюдаемости в логах.

**Границы (чтобы не задеть другие ветки):**
- Работает **только** если в state есть зафиксированный `anchor.id` (режим «аналог/замена»).
- Не трогает режимы «подбор по типу», «вопрос про товар», «диагностика», `lookup_knowledge`.
- Не меняет саму HTTP-логику `search-catalog.ts` — фильтр применяется на слое оркестратора после возврата тула.

## Этап 3 — Relaxation hints (кейс светодиодных ламп)

**Файл:** `supabase/functions/_shared/v3-tools/schemas.ts` (описание инструмента `search_catalog` / системные подсказки цикла).

**Логика (только при `v3_relaxation_hints_enabled = true`):**
Добавить в подсказки к `search_catalog` короткий инвариант:
- Если `total: 0` подряд ≥ 2 раза в одной ветке — на следующем шаге снять **один** самый узкий фильтр (по приоритету: цветовая температура → мощность → бренд → форма/цоколь → категория).
- Не вызывать `discover_category` больше 2 раз за сессию.
- После 3 пустых попыток — сделать один широкий `by_filter` только по листовой категории без опций.

**Границы:**
- Только текст промпта, никакой новой логики в оркестраторе.
- Флаг выключен — промпт идёт как сейчас, поведение других веток не меняется.

## Этап 4 — верификация на Preview

Порядок включения — по одному флагу:

1. Включить `v3_anchor_filter_enabled` → прогнать кейс `Кабель КГтп 3*6 ГК ГОСТ` и 3 контрольных кейса из QA-25, где НЕТ якоря (C04, C07, C12) — убедиться, что ничего не сломалось.
2. Включить `v3_relaxation_hints_enabled` → прогнать «светодиодные лампы» и те же 3 контрольных.
3. Смотрим `chat_request_logs.steps` — ищем `anchor_excluded:*`, отсутствие `no_progress_break` там, где раньше рвалось.

## Этап 5 — откат

Любой из флагов → `false` в `app_settings`. Мгновенный откат без деплоя, код старого поведения остаётся живой веткой.

## Что НЕ трогаем

- `search-catalog.ts` (HTTP-клиент к 220volt).
- `render.ts`, форматирование карточек, бренд, наличие.
- Другие ветки классификатора (аксессуары, spec_query, диагностика).
- Легаси V1 (`chat-consultant`) и V2 (`chat-consultant-v2`).

## Технические детали

- Тип колонок: `boolean not null default false`.
- Загрузка флагов: там же, где сейчас читаются `expert_interpretation_enabled` и `compare_branch_enabled`.
- Anchor filter: чистая функция `filterAnchorFromResults(result, anchorId): { result, excluded: boolean }` рядом с оркестратором + unit-тест на два случая (якорь есть в results / якоря нет).
- Каждый этап — отдельный approve, останавливаемся после миграции и ждём подтверждения перед этапом 2.
